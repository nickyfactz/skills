# Human Presentation Copy

Use this reference whenever writing or revising text that will be visible in the presentation.

## Target voice

Write like a strong human editor is helping the presenter sharpen their own words. Preserve the presenter's vocabulary, conviction, humor, skepticism, technical specificity, and degree of formality. The result may be polished, but it should still sound owned by a person.

## Copy hierarchy

1. **Headline:** the thought worth remembering.
2. **Support line:** the minimum context needed to interpret it.
3. **Labels / evidence:** concrete nouns, numbers, names, dates, or contrasts.
4. **Presenter detail:** anything that does not need to live on screen.

Do not move presenter detail into visible copy merely because there is empty space.

## Strong patterns

- Start on the claim instead of announcing the topic.
- Prefer concrete nouns and active verbs.
- Preserve meaningful first-person language when the presentation represents the user's work or point of view.
- Use exact examples and sourced numbers when they exist.
- Let short sentences land.
- Allow fragments in labels and visual callouts when they read naturally.
- Surface uncertainty plainly when it matters.
- Keep technical terminology when the audience needs it; explain it through structure or presenter notes rather than replacing it with vague language.

## AI-smell audit

Rewrite visible copy when it contains any of these patterns without a strong contextual reason:

- inflated adjectives with no evidence;
- generic claims such as "transformative", "game-changing", "next-generation", or "unlocking potential";
- performative transitions such as "let's dive in" or "in today's rapidly evolving landscape";
- redundant setup before the actual point;
- balanced three-item lists created only because three sounds polished;
- headings that say only `Overview`, `Background`, `Key Benefits`, `Challenges`, or `Conclusion` when a real claim is available;
- vague business language that could apply to any company or project;
- paragraphs that repeat the headline in longer words;
- invented confidence, metrics, customer sentiment, or outcomes;
- assistant self-reference or explanatory filler.

## Compression method

For each visible text block:

1. Identify the one idea the audience should retain.
2. Keep the strongest concrete evidence or contrast.
3. Remove setup the presenter can say aloud.
4. Remove duplicated meaning.
5. Read it aloud. If it sounds like copy nobody in the room would naturally say, rewrite it.

## Tone matching

Match the source human before applying a generic brand voice. A technical architecture review can remain technical. A product pitch can be punchy. A research lecture can be precise and curious. An internal project narrative can sound candid.

Professional does not mean bloodless. Polish does not mean corporate filler.
